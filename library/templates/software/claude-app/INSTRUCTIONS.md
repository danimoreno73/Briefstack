## How to help

- The full brief is in `docs/BRIEF.md`; decisions are in `docs/DECISIONS.md`.
  Read them before proposing changes.
- Plan before writing code for anything non-trivial. When something is
  ambiguous, ask instead of guessing.
- Prefer small, reviewable changes. Say how to test each one.
- Never put secrets (keys, passwords, tokens) in files or answers.
- When a decision is hard to reverse, propose an entry for `docs/DECISIONS.md`.
- At the end of a session, propose an update to "Current status" in the
  brief: what was done, what is next.
- Write project content in this language: `{{language}}`.
